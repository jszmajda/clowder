# Navigation & Input Specs (TUI-NAV)

## Key Model

- [x] **TUI-NAV-001**: The system shall map keys only from the tmux-safe set — plain printable characters, Tab, BackTab, Enter, Esc, Space, Backspace, and the four arrow keys — plus Ctrl-C as emergency quit; no other Ctrl chord, Alt/Meta, or function key shall be bound.
- [x] **TUI-NAV-002**: While a screen is focused with no prompt or overlay open, the system shall move the list cursor on ↑/↓ (and j/k), and perform the focused row's primary action once on Enter.
- [x] **TUI-NAV-003**: When Space (or i) is pressed on a focused row, the system shall toggle the inspector for that row.
- [x] **TUI-NAV-004**: The system shall treat uppercase as the modifier tier with X its only member — x opening the count prompt and X acting to the maximum affordable on the rows TUI-NAV-011 and TUI-NAV-012 name — and shall bind no other uppercase letter, so an uppercase screen mnemonic is ignored as any unbound key is and never acts in bulk.
- [x] **TUI-NAV-037**: While a count prompt or the palette is open — the palette being a field under this rule, not a full-screen overlay under TUI-NAV-052 — the system shall suspend every global single-key binding, so a digit types rather than jumping to a section: the palette shall take every printable character, digits and Space included, into its query, and the count prompt shall take the digits 0–9 into its count and ignore every other printable character and Space with no text and no footer note. Enter shall go to the field — reaching the row beneath only as the field's own acceptance directs (the count prompt's ×N), never as that row's primary action, and never committing an armed row beneath — and Esc shall cancel the field with no effect.
- [x] **TUI-NAV-058**: While a count prompt or the palette is open, Backspace shall delete the field's last character, doing nothing on an empty field, and never fire its global decrement.
- [x] **TUI-NAV-059**: While a count prompt or the palette is open, the arrow keys, Tab, and BackTab shall do nothing, so neither the list cursor nor the focused section moves beneath a field.
- [x] **TUI-NAV-060**: The system shall never close an open count prompt or palette on a timer: it stays open, the simulation advancing beneath it, until Esc closes it or an Enter the field acts on does — the count prompt's Enter always (applying the count, or cancelling on an empty or zero one), the palette's only when it has a result to jump to.
- [x] **TUI-NAV-061**: When Enter accepts a count prompt or the palette, the system shall not let a held or auto-repeating continuation of that press perform the primary action of the row focused once the field closes — only a distinct Enter, as TUI-NAV-051 requires of a heavy row's commit, acts on that row.
- [x] **TUI-NAV-066**: While a count prompt or the palette is open, the hint bar shall show that field's own keys — for the palette, typing to find, Enter to jump, and Esc to close — in place of any other context's keys, an armed row's beneath the field included.
- [x] **TUI-NAV-052**: While a full-screen overlay (Journal or help) is open, the system shall give the overlay the cursor, section, and action keys for its own navigation and suspend their global meanings, while keeping the speed keys, q, Ctrl-C, and Esc live — so the player can always retime, leave, or close from anywhere.

## Navigation

- [x] **TUI-NAV-005**: The system shall assign sections to the digits 1–0 by a fixed design-time map that never renumbers; pressing a section's digit jumps to it, and pressing the digit of an unrevealed section is a no-op with a footer note.
- [ ] **TUI-NAV-006**: The system shall reveal a section's tab only once at least one of its rows is revealed, place it in its fixed digit slot when it appears, and badge a newly appeared tab until it is first visited.
- [x] **TUI-NAV-007**: Tab/BackTab, l/h, and →/← shall cycle only revealed sections; ↓/↑ and j/k shall move within the focused list; [ and ] shall jump between the list's group headers.
- [x] **TUI-NAV-008**: The system shall remember each section's focused item by content identity (not list index), so returning to a section restores the same item even after intervening reveals inserted rows.
- [x] **TUI-NAV-038**: When / is pressed on a screen with no prompt or overlay open, the system shall open a find-anything palette over the results TUI-NAV-063 defines, narrow them as characters are typed to those whose displayed name contains the query, ignoring case, and on Enter close the palette, move to the top result's section, and focus that item's first row there, performing no row action; Esc shall close the palette with no effect.
- [x] **TUI-NAV-062**: The palette shall match the query as typed, spaces included, ignoring case in every comparison, and order the matching results by closeness — a name equal to the query first, then names beginning with it, then names containing it elsewhere — with ties in tab-bar order and then in each section's list order; a query that is empty or only spaces shall list every result in tab-bar then list order. The list shall be drawn from its top, so the result Enter takes is the first one shown and always on screen.
- [x] **TUI-NAV-063**: The palette's results shall be exactly the items listed in revealed sections, re-derived from current state as the simulation advances: one result per item with a selectable row, an item carrying several rows in its section counting once and group headers never counting — so a Teased item appears and an item with no row never does. Each result shall show the name its rows display, beside its section's digit, and two items sharing a name shall never be merged into one result.
- [x] **TUI-NAV-064**: When Enter is pressed in the palette with a query that is empty, only spaces, or matches nothing, the system shall do nothing, leaving the palette open with its query as typed.
- [x] **TUI-NAV-065**: When the palette's Enter moves to its top result, the system shall treat the move as navigation — disarming any armed row, dismissing the report banner, and counting as a visit to the section it lands in, as any other navigation does — and shall leave the layout as it was, so a narrow-mode inspector swap stays in place and shows the landed row.

## Action Model

- [x] **TUI-NAV-009**: The system shall render each actionable item as a row carrying a glyph-first availability marker (● affordable, ◐ partial, ○ revealed-unaffordable, ✓ owned/done), the flavor name, owned count, and next cost; Teased rows render dimmed with their marker and Hidden content is not rendered.
- [x] **TUI-NAV-053**: The system shall take every answer behind a row's marker, and behind a content row's presence, from a core query, deriving no coverage from a price and drawing no threshold of its own: a content row shall be listed exactly while the core reports its item Teased or Available and its command's gate open, whatever the stock, and a kind the core reports as present or absent shall be shown only as one or the other, never dimmed as Teased; a content row's marker shall follow the core's lock reason for its item — ✓ where the reason is that the item is already the player's, ● where the core reports no reason, ◐ or ○ where the reason is a shortfall as the core reports some or no coverage of the item's price, and ○ for any other reason, whatever the coverage — save a craft's tinkerer count row, which, like an actionable row with no content item, shall wear ● while listed; and a display-only row shall wear no marker.
- [x] **TUI-NAV-010**: While Enter is held on a row that is not a heavy action, the system shall repeat the focused row's action at no more than ten times per second regardless of the terminal's key-repeat rate, and the cursor shall not move on action.
- [x] **TUI-NAV-051**: The system shall commit a heavy action only on a distinct, deliberate second Enter — a held or auto-repeating Enter shall arm the row and go no further, and X shall never commit a heavy action — so no heavy action can be reached by holding a key.
- [x] **TUI-NAV-011**: When x is pressed on a focused row whose command is tagged count-taking or repeat-N, or on a count row — the heavy DeepNap row included — and the core does not report the row's content item as already the player's (TUI-NAV-041), the system shall open a count prompt on that row that captures digit input and previews as TUI-NAV-067 has it; Esc shall close the prompt with no effect.
- [x] **TUI-NAV-070**: When a count prompt's Enter accepts a nonzero count, the system shall pass the count once to a count-taking command, or call a repeat-N row's command or a count row's assign that many times, the core arbitrating each call — except on DeepNap, whose prompt's Enter arms the row as TUI-NAV-036 has it.
- [x] **TUI-NAV-071**: The system shall open the count prompt without an affordability pre-check, so a Teased or unaffordable row opens it as an affordable one does and its Enter attempts the count for the core to accept or reject.
- [x] **TUI-NAV-072**: The system shall hold an open count prompt to the row it was opened on by that row's content identity, never acting on another row; if that row is not listed when the prompt's Enter is pressed — having left its list as the simulation advanced — the prompt shall close with no effect and a footer note that the row has gone.
- [x] **TUI-NAV-067**: While a count prompt holds a nonzero count N on a row that is listed, the system shall preview what N will cost as the core reports it: on a repeat-N row, the core's total for taking N from current state, escalation included (SIM-ENG-038), or the count alone where that total names no resource; on a Pounce or Trade row, N times the price of one unit the core reports (SIM-ENG-047), per component, or the count alone where the core reports none; and on the DeepNap row or a count row, the count alone. An empty or zero count, or a prompt whose row is not listed, shall preview nothing.
- [x] **TUI-NAV-068**: The system shall bound a count prompt's count by the same shell-side cap that bounds X: a digit that would carry the count past the cap shall not be taken and shall leave a footer note that the count goes no higher, so the prompt always shows the count its Enter will use.
- [x] **TUI-NAV-069**: When a run that repeat-calls a command — a count prompt's ×N on a repeat-N or count row, or X — has a call rejected, the system shall surface that rejection as the plain-language footer of TUI-NAV-014, stating how many calls were done (and, for ×N, of how many) whenever at least one was, so a run rejected on its first call reads as Enter's rejection does; a run that reaches its count or X's cap unrejected shall leave no footer.
- [ ] **TUI-NAV-012**: When X is pressed on a focused row that is not a heavy action, that the core does not report as already the player's (TUI-NAV-041), and whose command is tagged count-taking or repeat-N (TUI-NAV-031), or on a count row, the system shall apply the row's action repeatedly, one unit per call — a repeat-N command as it stands, a count-taking command with a count of one, a count row's assign — until the core rejects it or a shell-side iteration cap is reached.
- [x] **TUI-NAV-013**: On a count row (jobs, tinkerers), the system shall assign one worker on + or Enter and unassign one on - or Backspace.
- [x] **TUI-NAV-014**: When a command is rejected by the core, the system shall surface the CommandError as a plain-language footer message for a few seconds and shall not open any blocking dialog.
- [x] **TUI-NAV-015**: For the heavy actions (GreatMeadowMove, PassItDown, AdoptRule, DeepNap), the first Enter shall arm the row — expanding it in place to the consequence summary TUI-NAV-075 defines — and only a second Enter while the arming holds (TUI-NAV-076) shall commit; the simulation keeps advancing throughout.
- [x] **TUI-NAV-075**: The system shall fill an armed row's consequence summary only with what the core reports from current state, re-derived on every frame while the row is armed, and with no consequence the shell works out by a rule of its own nor any judgement of whether the commit will be accepted: on the GreatMeadowMove row, the clowder's kitten count (away kittens included), the basket's room, and the share of stores the chest carries, stating nothing of what the Move earns or which stocks it keeps whole; on the PassItDown row, the elder wisdom stock that passes down; on an AdoptRule row, the sibling rule its definition names as the one it closes for the meadow; and on the DeepNap row, the armed year count, the core's cost for a nap of that length, and the wake-year as the core's current year plus that count. A figure the core reports that is not finite shall be stated in plain words as beyond reach, never printed.
- [x] **TUI-NAV-076**: An arming shall end silently at the first of: its expiry, about eight seconds of wall-clock time after it began, whatever the game speed; any navigation key on the screen, whether or not the key moves the cursor or section; the palette's jump (TUI-NAV-065); Esc closing it; its commit, whether the core accepts or refuses it; the arming of another row; or its row no longer being listed. Toggling the inspector, opening an overlay, the palette, or a count prompt, the keys an open Journal or help overlay takes for its own scrolling, the speed keys, the simulation advancing, and a change of layout shall leave it armed with its expiry still running.
- [x] **TUI-NAV-077**: While a row is armed, the system shall show it expanded beneath itself in the list, carry the same summary in the inspector while the narrow-mode swap shows the inspector in the list's place, and show the armed row's keys in the hint bar wherever no field or full-screen overlay holds the keyboard; the moment the arming ends, the row shall collapse and nothing on screen shall still show it armed.
- [x] **TUI-NAV-016**: When q is pressed, the system shall save and quit immediately with no confirmation; Ctrl-C shall also save and quit.
- [x] **TUI-NAV-039**: The system shall make every player-facing Command variant that belongs to a section reachable as a list row in that section — including the stand-down choice on a declare list and the unassign action on a count row — so that no sectioned command is reachable only through a mnemonic, the palette, or an accelerator key; the two commands belonging to no section (SetSpeed, ObserveSky) are reachable by their global keys instead.
- [x] **TUI-NAV-040**: The system shall bind ObserveSky to o from every screen; while no sky-event window is open the key shall be a no-op with a footer note.
- [x] **TUI-NAV-041**: On a row whose content item the core reports as already the player's, the system shall treat Enter, x, and X as no-ops with a footer note that it is already the player's, checked before anything else the key would do so an owned heavy row never arms. On a row whose command is tagged single, or a display-only row with no command, x and X shall be no-ops with a footer note that there is nothing to count; X on a heavy row of any tag, DeepNap included, shall instead be a no-op with a footer note that the row takes a deliberate Enter, not X (TUI-NAV-051).
- [x] **TUI-NAV-042**: The system shall ignore a printable key with no binding in the current context and show no footer message, and shall show a footer note only for a key that is bound but not meaningful in the current state.
- [x] **TUI-NAV-043**: Arming a heavy row shall reserve no resources and shall disarm any previously armed row; the committing Enter shall re-run the real command so the core re-validates it against current state, and a commit that is no longer valid shall fail to the footer like any other rejection.

## The Inspector

- [x] **TUI-NAV-017**: Where the terminal is at least about 100 columns wide, the system shall show the inspector as a persistent pane that live-updates for the focused row; on an 80-column terminal, Space shall swap the inspector in place of the list (and Space or Esc returns), never as a popup that stops the render or sim.
- [x] **TUI-NAV-018**: The inspector shall describe the row the cursor is on, its figures in the form of TUI-RENDER-012 and its name in the form of TUI-RENDER-014: the row's flavor name; a mechanical statement in the content definition's own terms, per copy or per worker — for a kind whose definition carries a blurb, that blurb and none of its effect fields; for any other kind, every field the definition carries apart from its name, its price and that price's escalation, its reveal threshold, and its gates, wherever the field departs from its nothing-special value, per-tick fields stated per game second — stating no price, no total for the copies owned, no yield after mood, and no stand-in sentence where nothing is left to state or the row's action has no definition; the copies held of a structure or a rite; on a job's count row the kittens in the meadow holding that job, and on a craft's tinkerer count row the tinkerers in the meadow bound to that recipe, counting no kitten who is away; the next cost and wait of TUI-NAV-078; and the lock reason of TUI-NAV-079.
- [x] **TUI-NAV-078**: On a row that takes a content item — a build, research, purchase, or make row, or a job's count row — the inspector shall state as its next cost the core's price for one more (SIM-ENG-038), per component with need and have, marking components only as the core's lock reason reports them — short by the amount a shortfall names, covered where a shortfall leaves the component out or the core reports no reason, and unmarked where another reason holds — and beside each component the core reports short, a wait in real time: the shortfall divided by the core's net rate for that resource and by the current speed, never rounded to sooner, replaced by a note that the stores cannot hold that much yet where the need exceeds the cap the core reports, or otherwise by a note that the stock is not growing where that rate is zero or less. The inspector shall state no next cost where the core's price names no component, on a craft's tinkerer count row, or where the core reports the item already the player's; and on a Pounce or Trade row it shall mark no component of the one-unit price of TUI-NAV-073 and state no wait beside it.
- [x] **TUI-NAV-079**: The inspector shall state the core's lock reason for the item a row takes (SIM-ENG-031) in plain words, exactly where the core reports one, with a distinct wording for each of the core's six reasons — a shortfall naming each short component and its amount, or that the price is not yet met where the core names no component; not-yet-reached saying nothing further; a prerequisite unmet, unnamed; the item already the player's; no kitten in the meadow free to take it on; no room for it yet — inferring no reason from a Teased availability or from stock, and stating none on a craft's tinkerer count row or a row with no content item.
- [x] **TUI-NAV-080**: On a stores row, the inspector shall state the resource's exact stock, the cap the core reports for it or that it has none, and the core's net rate for it per game second.
- [x] **TUI-NAV-073**: On a focused Pounce or Trade row, the inspector shall state as its next cost the price of one unit — one squad, or one caravan to that row's colony — as the core reports it (SIM-ENG-047), per component with have/need.

## Glanceability

- [x] **TUI-NAV-019**: The system shall keep persistent chrome on screen at every supported size: a header (clowder name/generation, date, kitten count, mood as a word, current speed, and the attention chips), the tab bar, a resource sidebar, an event ticker, and the hint bar.
- [ ] **TUI-NAV-020**: The system shall render the attention chips as glyph+count+word (never color alone) and show a chip only when its opportunity is live: ◦N idle (unassigned kittens), !sky (an open sky-event window), ★N new (content revealed since last viewed), and ~away (an unread offline report); when no opportunity is live the chip cluster is empty.
- [x] **TUI-NAV-054**: The system shall count in the idle chip only kittens the player can assign right now, excluding any kitten who is away from the meadow, so that no chip asks for an action the player cannot take.
- [x] **TUI-NAV-021**: The system shall render every UI symbol as a single-width character and shall use no emoji or ambiguous-width glyphs.
- [ ] **TUI-NAV-022**: The system shall convey affordability, mood, capped-storage, and attention through at least one non-color channel (glyph, word, or fill) so the game is fully playable without color perception.
- [ ] **TUI-NAV-044**: The system shall clear each attention chip on its own signal — the new-content chip when its badged section is visited, and the away chip once no report stays unread, each report being read as TUI-NAV-050 states.
- [x] **TUI-NAV-049**: The system shall list every revealed resource as an inspectable row in the home section's stores group, keeping the resource sidebar a curated display-only glance rather than the complete table.

## Discoverability

- [x] **TUI-NAV-023**: The system shall display a persistent hint bar whose keys adapt to the focused context, ordered most-relevant-first and always ending with the help key, and shall surface the count key the first time a count-taking row is focused.
- [x] **TUI-NAV-074**: While the focused row is a repeat-N row or a count row that x opens the count prompt on (TUI-NAV-011), and neither a field nor an armed row holds the hint bar, the hint bar shall show the count key, as it does on the count-taking rows TUI-NAV-023 names; it shall show the count key beside no row x does not open the prompt on, and shall show the max key only beside a row X runs on (TUI-NAV-012), never beside a heavy row.
- [ ] **TUI-NAV-024**: On a new game the only revealed section shall be the Meadow with its gather action focused, so the first learnable actions teach the cursor/Enter/Space/Tab backbone.
- [x] **TUI-NAV-025**: When ? is pressed, the system shall show a help overlay listing the full key map and the glyph legend.
- [x] **TUI-NAV-045**: When the hint bar's context keys exceed the available width, the system shall drop the least-relevant keys first and always retain the help key last, the complete key map remaining available through the help overlay.
- [x] **TUI-NAV-046**: The system shall bind a mnemonic only as a lowercase letter that the global key table leaves unbound, standing for one row listed on its screen that is not a heavy action — so an action already reachable by cursor and Enter — with no letter standing for more than one row on a screen at once. A fixed mnemonic shall be live while its row is listed on the focused screen, and a focused-item mnemonic while the cursor is on a row of an item whose rows include the one it stands for; a mnemonic shall be bound only while live and only where the global key table applies, never while a field or full-screen overlay holds the keyboard, and a letter that is not live shall be ignored as an unbound key, with no footer note.
- [x] **TUI-NAV-081**: When a live mnemonic is pressed, the system shall perform its row's primary action once, exactly as Enter on that row would, without moving the cursor or the focused section — so the press is not navigation, and leaves the report banner and the layout as they stood — and while the key is held or auto-repeats shall act no more than ten times per second regardless of the terminal's key-repeat rate.
- [x] **TUI-NAV-082**: Wherever the hint bar shows the focused row's keys — no field, full-screen overlay, or armed row holding it — the system shall name there every live mnemonic whose row is not the focused row, and no other letter as a mnemonic: a focused-item mnemonic directly after the key that names Enter, and the fixed mnemonics, in their rows' list order, after every other context key and before the help key.

## Events & Offline Report

- [x] **TUI-NAV-026**: The system shall render typed events into a dim ticker and, on e, a scrollable Journal overlay over the retained journal — the recent-event window plus every milestone and report the core has kept — which survives closing and reopening the game; no event shall flash, block, or expire unseen while it is retained.
- [x] **TUI-NAV-057**: The system shall rank an event's prominence from the classification the core supplies — flavor quieter than mechanical, milestones marked — and shall not decide from the event's identity which tier it belongs to.
- [x] **TUI-NAV-027**: When the core retains a report as a journal entry — as it does for a load's catch-up spanning at least its minimum interval (SAVE-015) and for every accepted nap (SIM-DREAM-008) — judged from the journal and never from a minimum span the shell holds, the system shall present it as a non-blocking one-line banner and as a Journal entry pinned at the top of the Journal, which opens at its top, while the report is unread and, where opening the Journal read it, until that Journal closes, and kept in the scrollback by when it was retained once read and no open Journal holds it pinned, so dismissing the banner loses nothing; and shall give no banner to a report the core did not retain. The entry shall tell the whole report: its span, stated as more than that span with a gentle note that the meadow stopped counting there where the report is truncated; every resource whose stock changed, signed, gains before decreases and each largest first; each kitten who arrived, by name, once with its count where the report counts more than one; the kittens who wandered and who came home, as TUI-NAV-056 states them; and the seasons passed.
- [x] **TUI-NAV-050**: The system shall queue the reports retained this session as unread banners, showing one at a time, the newest unread first, while pinning every one as its own Journal entry, so no report is displaced unseen. A report shall be read at the first of its banner retiring while showing or the Journal opening — opening the Journal reading every unread report at once while leaving each entry pinned until that Journal closes — and a read report shall leave the queue. A report still unread when the session ends shall not be queued again on a later load.
- [x] **TUI-NAV-083**: Esc when no field, overlay, armed row, or narrow-mode inspector swap is open above the report banner, any navigation key on the screen — cursor, section, group, or digit, whether or not it moves anything — and the palette's jump shall each retire only the banner showing, bringing up the next unread one; with the swap in, Esc shall return the list view before any Esc retires the banner.
- [x] **TUI-NAV-084**: Acting (Enter, x, X, +/-, a mnemonic), toggling the inspector, the speed keys, opening help, the palette, or a count prompt, the keys a full-screen overlay takes for its own scrolling, and the simulation advancing shall leave the showing report banner showing.
- [x] **TUI-NAV-055**: The system shall fill the report banner's one line, in order, with how much time passed — for an absence the span the core reports, stated as more than that span where the report is truncated, and for a nap the nap's length in years as the core's nap event reports it; the largest gains — positive net changes only, largest first, at most three, each resource named as its stores row names it, none too small to show as more than zero; the number of kittens who arrived, as the sum of the report's per-name arrival counts, where any did; and the hints for the tale and for dismissing — a quiet note standing in place of the gains where no stock grew and no kitten arrived — and shall read nothing of wanderings, returns, seasons passed, or falling stocks, leaving them to the pinned Journal entry, so the glance the player returns to leads with what grew, never with what left. Where the pane is too narrow for the whole line, the system shall drop whole clauses, never cutting one, in the order: the dismiss hint, the third gain, the second gain, the tale hint, the arrivals, the largest gain or the quiet note standing in the gains' place — never the span — and the clauses that remain shall keep their order.
- [x] **TUI-NAV-056**: The system shall tell, in a report's pinned entry, each kitten who wandered during its span by name as a visit to the neighbour's yard that ends back home — naming where they went and that they come back — and each who came home by name as a homecoming, each name once per list with its count where the report counts more than one, stating occurrences and never whereabouts, so the entry never says who is away now; and shall never render a departure as a loss, a kitten total net of departures, or a count decrease.

## Speed & Layout

- [x] **TUI-NAV-028**: The system shall change game speed one notch along 0.25→0.5→1→2→4→8 on < and >, applying SetSpeed and always showing the current speed in the header; from a loaded speed that is not on the ladder, the first press shall move to the nearest notch in the pressed direction, and at either end of the ladder a further press shall be a no-op.
- [ ] **TUI-NAV-029**: The system shall compute the layout as a pure function of terminal size with breakpoints, preserving the cursor, per-section item memory, armed state, and open overlays across a resize; below 80×24 it shall show a "terminal too small" card while the simulation keeps advancing.
- [ ] **TUI-NAV-030**: Esc shall only ever close the topmost transient (prompt, palette, overlay, armed row, or banner) and shall be a no-op on a bare screen; the system shall bind no Esc-prefixed key sequence, so a late Esc under tmux escape-time can never act, quit, or lose state.
- [x] **TUI-NAV-047**: The system shall apply a dead-band to the inspector's layout breakpoint so a single-column resize wobble does not flip the layout between the persistent-pane and swap modes.
- [x] **TUI-NAV-048**: Where the terminal is about 120 columns or wider, the system shall lay out three columns — sidebar, list capped for scannability, and inspector taking the remainder — giving extra width to the inspector and the ticker.

## Resolved Edge Cases

- [ ] **TUI-NAV-031**: The system shall tag the command each action row fires, the same wherever it appears, as exactly one of count-taking (the count is a command argument — Pounce, Trade, DeepNap), repeat-N (the shell calls the command N times — Build, Craft, and the buy commands), or single (every other command), and shall give a count row no tag; x passes N to a count-taking command and repeat-calls a repeat-N one, an empty or zero count cancels, and repeat-N calls run until one is rejected (partial success intended), how many copies of an item a buy takes being decided by the core's per-item refusal, never by the tag.
- [x] **TUI-NAV-032**: When entering a section with no remembered item (or whose remembered item is no longer revealed), the system shall place the cursor on the first Available row, else the first row.
- [x] **TUI-NAV-033**: Section cycling (Tab/BackTab, l/h, →/←) shall wrap around the revealed-section ring.
- [x] **TUI-NAV-034**: The system shall render the tab bar responsively — full [digit name] labels where they fit, else a compact digit strip that labels the focused and newly-badged tabs — never truncating a name mid-word and never scrolling a tab out of reach; the digit is the stable section identity.
- [ ] **TUI-NAV-035**: While the inspector occupies the list's space on a narrow terminal, ↑/↓ and j/k shall still move the underlying cursor with the inspector following it, and Space or Esc shall return to the list view.
- [x] **TUI-NAV-036**: For the DeepNap row, the count prompt's Enter on a nonzero count shall set the year count and arm the row with it — re-arming an already-armed row with the new count and a fresh expiry — while an empty or zero count arms nothing and leaves any arming as it stood; a plain Enter on the unarmed row shall arm a nap of one year.

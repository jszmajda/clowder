# Persistence Specs (SAVE)

## Format & Versioning

- [x] **SAVE-001**: The system shall serialize saves as pretty-printed JSON with the shape { save_version, saved_at_unix, state }, where saved_at_unix is supplied by the caller (the sim never reads clocks).
- [x] **SAVE-002**: If a save's save_version is newer than the binary understands, then load shall fail with a TooNew error naming the found version, never guessing forward.
- [x] **SAVE-003**: The system shall write saves atomically: serialize to a temp file in the same directory, fsync, then rename over the save file; a leftover temp file from a crashed write is ignored by load and overwritten by the next save.
- [x] **SAVE-004**: If the save file is absent, load shall return NotFound (the caller starts a new game); if the file is unparseable, missing required fields, or references unknown content ids, load shall return a Corrupt error with detail — and core shall never delete, overwrite, or rewrite a save file during load.
- [x] **SAVE-005**: When a parseable save contains out-of-range numeric state, the system shall normalize it on load — numeric fields deserialize wide and clamp, stocks clamp to caps, counters clamp to range — rather than rejecting the save (the format is advertised as hand-editable).
- [x] **SAVE-011**: The system shall persist only canonical state — derived values (happiness, rates, season) are recomputed after load — including the bounded event journal, which is canonical because it records what the player has already lived through and cannot be recomputed from anything else.
- [x] **SAVE-014**: The system shall migrate a v2 save forward by giving it an empty journal — a save written before the journal existed has no history to recover — with migration fidelity tested against a committed v2 fixture file.
- [x] **SAVE-025**: When a save's journal holds an entry whose event was written before that event gained data, the system shall load the entry with the added data at its default — an empty list, a count of zero — within the save's own version, with no version step.
- [x] **SAVE-015**: When catch-up spans at least a minimum interval, the system shall record the resulting OfflineReport into the journal as a retained entry, so a report survives being dismissed unread or the game being closed before it is read; a catch-up below that interval shall record nothing.
- [x] **SAVE-017**: The system shall carry, alongside a save's timestamp, the count of ticks the caller had banked but not yet run, and shall replay those ticks as counted rather than re-deriving them from an interval — ticks earned at one speed and saved at another would otherwise be lost or conjured by the ratio between the two. A save written before the count existed shall migrate owing nothing: a count that was never written cannot be recovered from a timestamp and a speed, and guessing would hand the player ticks they never earned or take ones they did.
- [x] **SAVE-016**: The system shall expose the catch-up cap as part of its public surface, so a caller applying the same limit to an interval it observed itself uses this value rather than a copy of it, there being one rule for how much absence is replayed.
- [x] **SAVE-012**: Every persistence IO function shall take an explicit file path, with the default path helper resolving to the platform data directory + clowder/save.json.

- [x] **SAVE-013**: When loading a save whose save_version is older than the current version, the system shall migrate it forward one version at a time — added fields receive their new-game defaults, save a field that its version step's own spec derives from the save's existing state (SAVE-024), and existing state is preserved exactly — verified against a committed fixture file of each prior version.
- [x] **SAVE-023**: The system shall carry the engine's revealed-resource set (SIM-ENG-051) in a save as canonical state — that a store was once held and has since been spent to nothing cannot be recomputed — under a save version newer than any written without it, so an older binary refuses the save as too new rather than loading it and writing it back with the set dropped.
- [x] **SAVE-024**: When migrating a save written before the revealed-resource set existed, the system shall fill the set by applying the engine's reveal rule (SIM-ENG-048, SIM-ENG-049) once to the save's state as loaded and normalized, before any catch-up tick: revealing every resource whose stock stands above zero, so every store a prior version listed for that save is still listed, and every resource named in a price the core would state for that state; and revealing no other resource — with migration fidelity tested against a committed fixture file of the prior version.

## Offline Catch-up

- [x] **SAVE-006**: When loading with a caller-supplied now_unix, the system shall compute elapsed = max(0, now_unix − saved_at_unix), cap it at 365 days, and owe elapsed × 4 × speed ticks (speed = the save's persisted game-speed) as the load's catch-up, returning before replaying any of them; the catch-up shall replay its owed ticks through the core's replay entry point — the same simulation step as live play in every respect but journaling, which is history-keeping rather than a game rule — only as the caller advances it (SAVE-018).
- [x] **SAVE-007**: If now_unix is earlier than saved_at_unix (a backwards clock), then the system shall load the save unchanged with zero ticks replayed, never regressing or refusing the state.
- [x] **SAVE-018**: The system shall let the caller advance a load's catch-up by at most a count of ticks the caller chooses per call, reading no clock to decide how many to run, and shall report the catch-up's total owed ticks — the interval's ticks (SAVE-006) plus those the save carried as owed (SAVE-017) — and how many remain; the ticks replayed, their order, and the report folded shall be the same however the catch-up is divided into calls.
- [x] **SAVE-019**: When an advance replays a catch-up's last owed tick, the system shall finish it exactly as a one-call load would — the report completed (continuing any report the save carried, SAVE-022) and recorded in the journal under SAVE-015 — returning the caught-up state and report, bit-identical to a one-call load of the same save at the same now_unix.
- [x] **SAVE-020**: When the caller sets a catch-up down before its last owed tick, the system shall return the state so far, the count of ticks still owed, and the report so far — its span and truncated flag the catch-up's own, its contents folded from the ticks replayed so far and from any report the save carried — and shall record nothing in the journal, so a save carrying the count and the report (SAVE-017, SAVE-021) loses no owed tick and no replayed part of the tale, and the load that replays the rest tells the absence once.
- [x] **SAVE-021**: The system shall carry in a save the report so far of a catch-up set down before it finished, or none, as canonical state — it records what the meadow has already lived through and cannot be recomputed — under a save version newer than any written without it, so an older binary refuses the save as too new rather than dropping the tale; a save written before the report so far existed shall migrate carrying none.
- [x] **SAVE-022**: When a load's save carries a report so far, the system shall continue that report rather than begin a new one: its span the carried span plus the load's capped interval, its truncated flag set where either was truncated, its net deltas the carried deltas plus the replay's against the state as loaded, its name lists merged with each name's counts summed, and its seasons passed summed; and SAVE-015's minimum-interval rule shall judge it by that whole span, so a relaunch soon after a quit mid-replay still retains the absence's report.
- [x] **SAVE-008**: The system shall fold catch-up replay events into an OfflineReport containing the elapsed span, a truncated flag when the 365-day cap applied, per-resource net deltas, gross name lists of kittens arrived/wandered/returned aggregated with counts per name (a kitten may appear in more than one list, and more than once per list), and seasons passed. (Commands cannot occur during replay, so the report never contains builds or research.)
- [x] **SAVE-009**: Replaying 30 days of offline time shall complete in under 5 seconds in a release build.
- [x] **SAVE-010**: A save/load round-trip with zero elapsed time shall reproduce bit-identical game state, verified by comparing serialized bytes (which requires canonical collection ordering per SIM-ENG's determinism contract).
